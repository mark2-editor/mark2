# Git 工作流

Git 是一种记录文件修改的工具。可以把它想成一个文件夹的“时间线”：你可以查看哪里变了，保存一个带名字的检查点，需要时回到之前的检查点。Mark2 把常用操作做成了图形界面，不需要打开命令行。

## 你会看到的几个词

| 词语 | 通俗解释 |
| --- | --- |
| Repository（仓库） | Git 正在记录变化的文件夹 |
| Commit（提交） | 一个带名字的保存检查点 |
| Branch（分支） | 一条独立的修改路线，适合安全地尝试新想法 |
| Remote（远程仓库） | 仓库保存在服务器上的另一份副本 |
| Stage（暂存） | 选择哪些修改要放进下一个检查点 |

## 开始使用

先安装 Git，然后在 Mark2 中打开属于 Git 仓库的文件或文件夹。如果 Mark2 提示找不到 Git，说明 Git 尚未安装，或系统暂时无法找到它。

打开 **Git** 面板，可以看到当前分支、已修改文件和已暂存文件。接下来：

1. 打开 diff，查看具体改了什么。
2. 暂存想要放进下一个检查点的文件或修改。
3. 输入简短说明，选择 **Commit（提交）**。

Mark2 可以使用 AI 根据当前修改建议提交说明，你可以先检查并修改，再完成提交。

## 使用分支和远程副本

当你想尝试一种新写法，又不想影响当前版本时，可以创建一个分支。完成尝试后，再切换分支或将它合并回来。

如果仓库配置了远程副本，可以使用 **Fetch**、**Pull**、**Push** 或 **Sync** 同步两边的修改。当 Mark2 询问如何合并不同修改时，**Merge** 会保留两条路线并新增一个检查点；**Rebase** 会把你的修改接到远程最新修改之后，更适合已经熟悉 Git 的用户。

## 暂时放下未完成的修改

**Stash** 可以把还没做完的修改暂时收起来，让你先处理其他事情。之后可以 Apply 或 Pop，把它们放回来。

如果两处修改碰巧改到了同一行，Git 会报告冲突。Mark2 会列出冲突文件，你可以选择其中一边，或手动编辑文件。完成后保存、暂存已解决的文件，再继续操作。

可能会改动磁盘文件的 Git 操作开始前，Mark2 会提醒你先保存未保存的文档。
