# Git 工作流

Git 为文件夹记录变更历史。Mark2 将常用操作集中在可视化面板中，便于在编辑文档时审阅和提交修改。

## 使用前准备

需要安装 Git，并确保系统可以找到它。打开已有 Git 仓库中的文件或文件夹，再打开 **Git** 面板。未检测到仓库时，先确认打开的位置是否正确。

本地提交不要求配置远端。远端操作需要远端地址和有效的 Git 身份验证；AI 凭据不能用于 Git 认证。

## 常用术语

| 术语 | 含义 |
| --- | --- |
| 仓库 | Git 跟踪变更的文件夹 |
| 工作区 | 当前磁盘上的文件状态 |
| 差异 | 展示内容变更的比较结果 |
| 暂存 | 选择要放入下一次提交的变更 |
| 提交 | 带说明的变更记录节点 |
| 分支 | 独立的一条工作线路 |
| 远端 | 仓库的另一份副本，通常托管在线上 |

## 创建一次提交

1. 按 **⌘S** 保存文档，让 Git 读取到磁盘上的最新内容。
2. 打开 Git 面板，选择有变更的文件。
3. 查看差异，检查意外修改与不应提交的私密文件。
4. 暂存属于同一任务的文件或变更。
5. 输入简短说明，例如 `docs: clarify setup steps`。
6. 选择 **提交**，确认历史中出现新记录。

提交包含暂存的变更，不包含所有未保存草稿。暂存后又修改文件时，需要重新检查并暂存新增变更。配置 AI 后，可以生成提交说明建议；提交前仍需检查内容。

## 使用分支

进行较大改写前，可以创建分支，例如 `revise-installation-guide`，在分支上修改并提交。

切换分支前检查未提交变更，先提交或存储（stash）需要保留的工作，并处理 Git 关于本地变更冲突的提示。切换分支会改变磁盘文件。

## 使用远端

| 操作 | 用途 |
| --- | --- |
| 获取（Fetch） | 下载远端变更信息，不立即整合到当前分支 |
| 拉取（Pull） | 获取并整合远端变更 |
| 推送（Push） | 将本地提交上传到已配置的远端 |
| 同步（Sync） | 按面板选择的策略协调传入与传出变更 |

同步前检查领先或落后的提交数。只有成功推送后，本地提交才会出现在远端。

**合并（Merge）**连接不同工作线路，可能创建合并提交。**变基（Rebase）**在另一段历史之后重新应用本地提交，会改变提交标识。遵循项目约定，在共享工作上执行前检查操作范围。

## 处理冲突

冲突表示 Git 无法自动合并重叠修改。

1. 打开冲突文件，检查两边的内容。
2. 保留正确文本，移除 `<<<<<<<`、`=======`、`>>>>>>>` 等冲突标记。
3. 保存并暂存处理后的文件。
4. 按 Git 面板提示继续当前操作。
5. 推送前检查最终文档。

## 历史与恢复

通过提交差异了解旧变更。还原提交（revert）会新增一个提交来撤销旧提交，适合已经分享的变更。丢弃工作区修改会移除未提交内容，执行前应检查具体范围。
